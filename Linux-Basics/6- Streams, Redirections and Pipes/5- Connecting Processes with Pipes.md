# Connecting Processes with Pipes and Pipelines

In previous lessons, we redirected streams to and from files on disk using `>`, `>>`, and `<`.

However, in day-to-day operations, you frequently need to take the output generated by one command and immediately process it with another (such as a filter like `grep` or a counting tool like `wc`).

---

## 1. The Problem: Unfiltered Output Overload

Consider running `cat` on a system configuration file like `/etc/services` (or `/etc/hosts`). Files like these can span hundreds or thousands of lines:

```bash
abdullah@fedora:~$ cat /etc/services
```

```text
 ┌─────────────────────────────┐
 │       cat /etc/services     │
 └──────────────┬──────────────┘
                │
                ▼ [FD 1] stdout (Emits thousands of lines)
 ┌──────────────────────────────────────────────┐
 │ From shell back to your terminal as a result │
 │ (Screen floods with unreadable text)         │
 └──────────────────────────────────────────────┘
```

The shell dumps thousands of lines across your screen in a split second. Finding the specific line you need by manually scrolling through your terminal buffer is impractical.

---

## 2. Two Ways to Solve the Problem

To filter that massive stream through a tool like `grep`, you have two technical choices:

### Approach A: The Impractical Way (Writing to a Temporary File)
Before pipes, passing information between two programs required saving an intermediate file on your storage disk:

```text
                                  STEP 1: Write to Disk
 ┌─────────────────────────┐                                 ┌─────────────────────────┐
 │    cat /etc/services    │ ───[FD 1: stdout via >]───────► │    temp.txt on Disk     │
 └─────────────────────────┘                                 └────────────┬────────────┘
                                                                          │
                                  STEP 2: Read from Disk                  │
                                                                          ▼ [FD 0: stdin via <]
                                                             ┌─────────────────────────┐
                                                             │       grep "http"       │
                                                             └────────────┬────────────┘
                                                                          │
                                                                          ▼ [FD 1: stdout]
                                                             ┌─────────────────────────┐
                                                             │ Terminal Display Result │
                                                             └─────────────────────────┘
```

#### Step-by-Step Commands:
```bash
# Step 1: Save the massive output to an intermediate file on your SSD
abdullah@fedora:~$ cat /etc/services > temp.txt

# Step 2: Feed that file into grep
abdullah@fedora:~$ grep "http" < temp.txt
http            80/tcp          www             # WorldWideWeb HTTP
http            80/udp          www             # HyperText Transfer Protocol
https           443/tcp                         # http protocol over TLS/SSL
https           443/udp                         # http protocol over TLS/SSL

# Step 3: Remember to manually clean up your disk
abdullah@fedora:~$ rm temp.txt
```

**Why this is bad practice:**
* **Slow:** Forces the OS to do unnecessary disk writes and reads.
* **Cluttered:** Leaves temporary garbage files all over your directory.
* **Non-streaming:** Program B has to wait until Program A completely finishes writing the entire file before it can begin reading.

---

### Approach B: The Modern Way (Connecting Processes with a Pipe)
The vertical bar symbol (**`|`**) connects two programs directly in RAM:
* It takes **`stdout` (FD `1`)** of the command on the left.
* It attaches it directly to **`stdin` (FD `0`)** of the command on the right through an operating system memory buffer.

```text
 ┌─────────────────────────┐
 │    cat /etc/services    │
 └────────────┬────────────┘
              │ [FD 1] stdout
              ▼
    ┌──────────────────┐
    │   Kernel Pipe    │  (In-Memory Buffer in RAM)
    └─────────┬────────┘
              │ [FD 0] stdin
              ▼
 ┌─────────────────────────┐
 │       grep "http"       │
 └────────────┬────────────┘
              │ [FD 1] stdout
              ▼
 ┌──────────────────────────────────────────────┐
 │ From shell back to your terminal as a result │
 └──────────────────────────────────────────────┘
```

#### The Single Command:
```bash
abdullah@fedora:~$ cat /etc/services | grep "http"
http            80/tcp          www             # WorldWideWeb HTTP
http            80/udp          www             # HyperText Transfer Protocol
https           443/tcp                         # http protocol over TLS/SSL
https           443/udp                         # http protocol over TLS/SSL
```

Zero temporary files touch your SSD. Both processes run concurrently, and data streams seamlessly in memory.

## 3. Building Multi-Stage Pipelines

Piping is not limited to connecting just two commands. When you chain multiple pipes together in series, this structure is formally called a **Pipeline**:

```text
[ Producer ] ──|──> [ Filter 1 ] ──|──> [ Filter 2 ] ──|──> [ Final Consumer ]
```

Each stage in a pipeline receives the output of the previous stage, performs its dedicated task, and passes the modified stream down the line.

---

### Example A: Piping into `wc` (Word & Line Counting)
The `wc` utility acts as an aggregator along a pipeline:
* `wc -l`: Counts lines passing through `stdin`.
* `wc -w`: Counts words passing through `stdin`.

To count how many lines matched `http` without printing the raw text to your screen, chain `wc -l` onto the end of the pipeline:

```bash
abdullah@fedora:~$ cat /etc/services | grep "http" | wc -l
4
```

```text
 ┌─────────────────────────┐
 │    cat /etc/services    │
 └────────────┬────────────┘
              │ [FD 1] stdout
              ▼
    ┌──────────────────┐
    │      Pipe 1      │
    └─────────┬────────┘
              │ [FD 0] stdin
              ▼
 ┌─────────────────────────┐
 │       grep "http"       │
 └────────────┬────────────┘
              │ [FD 1] stdout (4 matching lines)
              ▼
    ┌──────────────────┐
    │      Pipe 2      │
    └─────────┬────────┘
              │ [FD 0] stdin
              ▼
 ┌─────────────────────────┐
 │          wc -l          │  (Counts line breaks)
 └────────────┬────────────┘
              │ [FD 1] stdout
              ▼
       Result: 4
```

To count the total words in that same filtered output, swap the flag to `-w`:

```bash
abdullah@fedora:~$ cat /etc/services | grep "http" | wc -w
24
```

---

### Example B: Piping into `head` (Limiting Matches)
Search for `ssh` service definitions, but limit the output to strictly the first two entries:

```bash
abdullah@fedora:~$ cat /etc/services | grep "ssh" | head -n 2
ssh             22/tcp                          # The Secure Shell (SSH) Protocol
ssh             22/udp                          # The Secure Shell (SSH) Protocol
```

```text
 ┌─────────────────────────────┐
 │      cat /etc/services      │
 └──────────────┬──────────────┘
                │ [FD 1] stdout
                ▼
       ┌──────────────────┐
       │     Pipe 1       │
       └────────┬─────────┘
                │ [FD 0] stdin
                ▼
 ┌─────────────────────────────┐
 │        grep "ssh"           │
 └──────────────┬──────────────┘
                │ [FD 1] stdout
                ▼
       ┌──────────────────┐
       │     Pipe 2       │
       └────────┬─────────┘
                │ [FD 0] stdin
                ▼
 ┌─────────────────────────────┐
 │         head -n 2           │
 └──────────────┬──────────────┘
                │ [FD 1] stdout
                ▼
 ┌──────────────────────────────────────────────┐
 │ From shell back to your terminal as a result │
 └──────────────────────────────────────────────┘
```

## 4. Summary: Redirection vs. Pipelines

```text
┌─────────────────┬────────────┬─────────────────────────────┬──────────────────────────┐
│ Mechanism       │ Operator   │ What It Connects            │ Where Data Travels       │
├─────────────────┼────────────┼─────────────────────────────┼──────────────────────────┤
│ Redirection     │ > , >> , < │ Process <───> File on disk  │ Persistent Disk Storage  │
│ Pipeline        │ |          │ Process <───> Process       │ In-Memory Kernel Buffer  │
└─────────────────┴────────────┴─────────────────────────────┴──────────────────────────┘
```

---

## Key Takeaways

* **What a Pipe Does:** It joins `stdout` (FD `1`) of the program on the left directly to `stdin` (FD `0`) of the program on the right.
* **Pipelines:** A sequence of two or more commands chained together using `|`. Data flows through each stage without ever touching disk.
* **Filter Synergy:** Small, focused commands (`grep`, `head`, `tail`, `wc`) combine along pipelines to build tailored data workflows.
* **Performance:** Operating system memory buffers make pipelines significantly faster than writing intermediate files to disk.
